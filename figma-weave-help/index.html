1.1 Media

Работа с медиа (Working with Media)

Источник →

Содержание: статья описывает базовые способы импорта медиафайлов в Weave — перетаскиванием на канвас (каждый файл становится отдельным элементом) или через Import Node (все файлы группируются в одном узле). Также рассказывается о сортировке медиа по имени или дате добавления через иконку сортировки. Отдельно описан режим отображения медиа-узлов: когда в одном узле (Import Node или GenAI-узле) находится несколько файлов, можно листать их по одному стрелками или переключиться в режим галереи, чтобы видеть все элементы сразу.

Вывод: используйте Import Node, когда нужно держать связанные файлы в одном узле, а drag-and-drop — когда файлы должны остаться независимыми; переключение single/gallery view упрощает навигацию по большим наборам генераций.

Галерея медиа (Media Gallery)

Источник →

Содержание: статья объясняет, как открыть сгенерированный результат в полноэкранном режиме галереи — кликом по иконке галереи в правом нижнем углу узла, либо наведением на узел и нажатием клавиши Space. Далее описывается, как посмотреть историю генерации файла: открыть галерею и нажать «Show info», после чего становятся видны использованный промпт, параметры и настройки генерации, а также номер seed и другие технические детали.

Вывод: режим галереи с «Show info» — основной способ проверить и воспроизвести параметры удачной генерации (промпт, seed, настройки) без необходимости пересоздавать узел.

Скачивание медиа (Downloading Media)

Источник →

Содержание: статья описывает несколько сценариев скачивания файлов из Weave. Через меню из трёх точек в правом верхнем углу узла можно скачать текущий файл или все файлы внутри узла. Если узлы объединены в группу, можно кликнуть правой кнопкой по области группы и выбрать «Download All», чтобы скачать все файлы группы сразу. Также можно выделить сразу несколько узлов рамкой выделения (click and drag) и через контекстное меню правой кнопкой мыши скачать файлы из всех выбранных узлов одновременно.

Вывод: для разовой выгрузки достаточно меню на узле, а для массовой выгрузки удобнее группировать узлы или выделять их рамкой и использовать «Download All» — это экономит время при работе с большими проектами.

Удаление файла из узла (Removing a file from a Node)

Источник →

Содержание: статья описывает два способа очистки узла от лишних генераций через меню из трёх точек в правом верхнем углу узла. Первый — «Remove Current Generation», который удаляет только выбранный (текущий отображаемый) файл. Второй — «Remove All Other Generations», который удаляет все файлы в узле, кроме выбранного, оставляя только один нужный результат.

Вывод: эти команды полезны для очистки узла после серии генераций — можно убрать один неудачный результат либо сразу оставить только лучший вариант, не удаляя узел целиком.

Вместе четыре статьи покрывают весь путь медиафайла в проекте — от появления на канвасе до финального отбора и выгрузки нужного результата.

1.2 Text and Prompts

Изменение размера текстового узла (Resizing a Text Node)

Источник →

Содержание: короткая статья объясняет, как изменить размер текстового узла в редакторе Weave, чтобы увеличить область отображения текста. Единственный описанный шаг — взять за край узла и перетащить его до нужного размера.

Вывод: это базовая, но необходимая операция при работе с текстовыми узлами — используйте её, когда содержимое не помещается в текущих границах узла и нужно расширить область отображения.

Переменные промпта (Prompt Variables)

Источник →

Содержание: статья описывает механизм переменных, который позволяет объединять несколько текстовых вводов в один главный промпт-узел. Чтобы создать переменную, нужно добавить Prompt Node и нажать «Add Variables» в его нижнем левом углу — появится новый входной хендл, к которому можно подключить любой Text Node, и он станет переменной. Также описаны режимы отображения переменных (через кнопку «Display»): Variable Source, Variable Value и Variable Source and Value. Переменные внутри узла можно перетаскивать мышью на нужную позицию.

Вывод: переменные стоит использовать, когда нужно собрать сложный промпт из нескольких управляемых текстовых блоков (например, переиспользуемых фрагментов) вместо того, чтобы переписывать один длинный промпт вручную — это упрощает организацию и модификацию промптов.

Итог по разделу «Text and Prompts»: раздел посвящён базовым операциям с текстовыми узлами и промптами — от простого изменения размера узла до продвинутого механизма переменных, позволяющего собирать составные промпты из отдельных текстовых блоков.

1.3 Navigating Weave

Навигация по канвасу (Navigating the Canvas)

Источник →

Содержание: базовые приёмы перемещения по рабочему полотну. Для панорамирования — инструмент «рука» (клавиша H) и перетаскивание мышью/трекпадом (двумя пальцами для скролла). Для масштабирования — зажатая Cmd (Mac) / Ctrl (Windows) при прокрутке колеса мыши, либо жест «щипок» на трекпаде.

Вывод: это базовая механика работы с канвасом — освоить её нужно в первую очередь, без неё неудобно работать даже с небольшим workflow.

Группировка и разгруппировка узлов (Group and Ungroup Nodes)

Источник →

Содержание: как объединять узлы в группы: выделить узлы и нажать Ctrl/Cmd+G или правый клик → Group Selection. Группу можно двигать целиком, перемещать отдельные узлы внутри неё (группа расширяется автоматически), сжимать под размер содержимого через «Resize to Fit». Описано редактирование заголовка, изменение его размера и цвета группы, разгруппировка и удаление отдельного узла из группы через контекстное меню.

Вывод: группировка полезна для организации сложных workflow с большим количеством узлов — позволяет визуально структурировать канвас и управлять частями схемы как единым целым.

Соединение рёбер / проводов (Connecting Edges (Wires))

Источник →

Содержание: механика создания связей: перетащить «провод» от входа или выхода узла. Если отпустить провод, вытянутый из выхода, на пустом месте канваса — появится меню выбора нового узла. При перетаскивании в существующий узел провод автоматически подключается к совместимому входу (текст к тексту, изображение к изображению) по порядку доступности входов. Для узлов с несколькими входами дополнительные слоты появляются автоматически.

Вывод: понимание автоматической логики соединений (по типу контента и по порядку входов) экономит время при сборке workflow и помогает избежать путаницы, когда провод «не подключается».

Удаление рёбер / проводов (Deleting Edges (Wires))

Источник →

Содержание: удаление связи между узлами: выделить провод правым кликом и нажать Delete, либо двойной клик по нему. Можно выделить сразу несколько проводов рамкой выделения и удалить их все одним нажатием Delete.

Вывод: удобно для быстрой пересборки workflow — массовое удаление связей рамкой ускоряет чистку сложных схем перед реорганизацией.

Разбираемся с узлами (Understanding Nodes)

Источник →

Содержание: узел — функция с входами (слева) и выходами (справа), обрабатывающая контент. Два типа: генеративные ИИ-узлы (кнопка Run, требуют кредиты, создают новый контент) и негенеративные узлы (ручные инструменты — painter, blur, объединение промптов — без кредитов). Добавление узлов — через боковое меню, клавишу Tab или правый клик; настройка параметров — через правую панель. Цветовая кодировка: зелёный — изображение, фиолетовый — текст/LoRA, красный — видео, синий — массив/3D, белый — множественные входы, лаймовый — маска.

Вывод: ключевая концептуальная статья для новичков — понимание типов узлов, их входов/выходов и цветовой кодировки нужно освоить до начала сборки любого workflow.

Инструменты (Tools)

Источник →

Содержание: функция Tools (ранее Design Apps) превращает workflow в переиспользуемый «дизайн-конструктор» с настраиваемыми атрибутами, которым можно делиться. Чтобы создать инструмент, нужно добавить Output-узел — откроется вкладка Tool. Видимые атрибуты берутся из узлов без входов (например, Prompt), их можно скрыть через контекстное меню. Публикация — кнопкой Publish; при шаринге только автор видит редактируемый режим, получатели — опубликованную версию с возможностью переключиться в режим экспериментов. Каждая публикация создаёт версию с меткой времени.

Вывод: Tools полезны, когда нужно превратить готовый workflow в шаблон/конструктор для многократного использования командой или клиентами — без пересборки схемы каждый раз.

Горячие клавиши (Keyboard Shortcuts)

Источник →

Содержание: Tab — меню узлов; Cmd/Ctrl+C/V — копировать/вставить; Cmd/Ctrl+D — дублировать узел(ы); Cmd/Ctrl+Z / Shift+Z — отменить/повторить; Cmd/Ctrl+P — новый Prompt-узел; перетаскивание провода с зажатым Option/Alt — подсказки узлов с автоподключением; V/H — переключение «Выделение»/«Рука»; Cmd+I — импорт файлов.

Вывод: стоит держать под рукой как шпаргалку — знание сочетаний заметно ускоряет сборку и правку workflow по сравнению с мышью и меню.

Редактор таймлайна (Timeline Editor)

Источник →

Содержание: таймлайн встроен в Compositor. Включается через Edit → Timeline — слои появляются как дорожки. Можно менять длительность видео и FPS, порядок слоёв перетаскиванием, обрезать начало/конец, включать/выключать видимость слоя (глаз), блокировать (замок) и отключать звук. Свойства слоя (прозрачность, blending, позиция, масштаб) — на правой панели.

Вывод: нужен при монтаже видео-результатов внутри Weave — это встроенный мини-видеоредактор для компоновки нескольких слоёв/видео в единый ролик.

Вывод: эти функции ускоряют массовую коммутацию узлов в сложных workflow — особенно полезны, когда нужно быстро подключить один источник к множеству целей.

Использование раздела «Сохранённое» (Using the Saved section)

Источник →

Содержание: раздел «Saved» в левой панели позволяет сохранять модели, узлы и группы узлов для повторного использования — доступны всем участникам рабочего пространства. Можно сохранить модель с кастомными настройками как именованный пресет (заменяет прежний раздел My Models), сохранить настроенный узел-инструмент, а также группу из двух и более узлов с названием, описанием и превью. Переименование/удаление — через режим редактирования (карандаш); доступ есть и из контекстного меню канваса (правый клик → Saved).

Вывод: раздел Saved стоит использовать для стандартизации часто повторяющихся настроек моделей и связок узлов в команде — экономит время и обеспечивает единообразие workflow между участниками.

Итог по разделу «Navigating Weave»: раздел охватывает полный набор базовых и продвинутых навыков работы с канвасом — от панорамирования и зума до понимания узлов, соединения/удаления, группировки, горячих клавиш, таймлайн-редактора видео и системы сохранённых пресетов. Блок статей «Delights» фиксирует итеративные UX-улучшения (массовое подключение узлов, распаковка результатов, импорт CSV в итераторы) — интерфейс Weave активно развивается в сторону ускорения сборки сложных workflow.

1.4 Import Models

Импорт моделей (Importing Models)

Источник →

Содержание: как импортировать сторонние генеративные модели в Weave из трёх источников — Fal, Replicate и CivitAi (доступно на тарифах Starter, Pro, Team и Enterprise). Процесс одинаков: перетащить узел Import Model на канвас (или через TAB и поиск), открыть страницу нужной модели на внешнем сервисе, скопировать URL и вставить его на канвас Weave или в сам узел — модель импортируется автоматически, параметры появляются на панели справа. Кнопка Save model сохраняет модель для использования во всех воркфлоу (раздел Saved).

Вывод: используйте эту функцию, когда нужной модели нет в стандартном наборе Weave, а она доступна на Fal, Replicate или CivitAi — импорт занимает пару кликов через вставку URL, а сохранение модели один раз делает её доступной во всех последующих проектах.

Импорт LoRA в Figma Weave (Importing LoRAs in Figma Weave)

Источник →

Содержание: как загружать собственные LoRA-модели для кастомизации стиля, персонажей или концептов. Узел Import LoRA (через toolbox или поиск «LoRA»), загрузка файла кнопкой Upload, подключение к совместимой модели (например FluxDev LoRA): текстовый промпт → вход «prompt», LoRA → вход «LoRA1». Сила влияния регулируется через Number node (1 = полный эффект, дробное значение 0–1 — мягче), подключается ко входу «LoRA1 scale». Поддерживается одновременное использование двух LoRA (второй — «LoRA2» / «LoRA2 scale»).

Вывод: LoRA стоит использовать, когда нужен специфичный, узнаваемый стиль или персонаж, недоступный в базовых моделях; ключевой инсайт — сила эффекта тонко настраивается через float-параметр scale, а комбинирование двух LoRA расширяет возможности, но требует экспериментов.

Итог по разделу «Import Models»: раздел показывает два способа расширить набор моделей за пределы встроенных — подключение готовых моделей из внешних платформ (Fal, Replicate, CivitAi) через вставку URL и загрузку собственных кастомизирующих LoRA-файлов с гибкой настройкой силы эффекта. Оба механизма построены вокруг узлов канваса и позволяют сохранять результат для повторного использования.

1.5 Preferences

Настройки предпочтений (Preferences Settings)

Источник →

Содержание: путь к панели предпочтений: иконка Weave в левом верхнем углу → прокрутить меню вниз → Preferences. В панели — набор опций, каждую можно включить/выключить отдельно.

Вывод: это входная точка для любой кастомизации поведения редактора Weave — с неё стоит начинать при изменении общих настроек рабочего пространства.

Изменение стиля wire-соединений (Changing Wire Styles)

Источник →

Содержание: изменение визуального стиля линий, связывающих узлы. Применяется глобально ко всем воркфлоу. Путь: логотип Weave → Preferences → Wire Style. Доступны три варианта: Elbow Style (ломаная под углом), Line Style (прямая), Bezier Style (плавная кривая).

Вывод: полезно для улучшения читаемости сложных воркфлоу — Bezier Style мягче для органичных схем, Elbow Style удобнее для строгих «схемотехнических» структур; настройка глобальная и повлияет на все воркфлоу.

Итог по разделу «Preferences»: единая точка входа ко всем персональным настройкам интерфейса — общий переключатель опций и выбор стиля отрисовки wire-соединений. Обе настройки применяются на уровне всего аккаунта/рабочего пространства.

Управление кредитами (Managing Credits)

4.3 Iterators

Итераторы (Iterators)

Источник →

Содержание: три типа: Text Iterator Node (объединяет несколько текстовых входов, отправляет одной модели, каждый промпт отдельно; входы вручную, через Array Node, Prompt Node или CSV-импорт), Image Iterator Node и Video Iterator Node (несколько входов импортируются, выбирается модель, генерирует результат для каждого входа отдельным прогоном).

Распаковка узла (Unpack a Node)

Источник →

Содержание: результаты батч-генерации хранятся внутри одного узла с переключением режимов отображения. Чтобы разделить их на отдельные узлы — три точки справа от узла → «Unpack».

Вывод: полезно, когда нужно продолжить работу с каждым результатом батч-генерации по отдельности — после распаковки все результаты становятся отдельными узлами, сгруппированными вместе.

Создание итератора из существующего узла (Creating Iterators from Existing Node)

Источник →

Содержание: итератор можно создать напрямую из узла, уже содержащего несколько результатов — три точки в правом верхнем углу → «Create Iterator».

Вывод: удобно, когда уже есть узел с набором сгенерированных результатов и их нужно использовать как входные данные для следующего этапа батч-обработки, не собирая итератор с нуля.

Итог по разделу «Iterators»: полный цикл батч-обработки — запуск батч-генерации текста/изображений/видео через одну модель, работа с результатами (распаковка в отдельные узлы) и повторное использование результатов как входа для следующей итерации.

Часто задаваемые вопросы по Figma Weave (Figma Weave FAQ)

Источник →

Содержание: Weavy приобретена Figma и стала Figma Weave. Для существующих пользователей ничего не меняется: аккаунты, проекты, кредиты, подписки, вход через app.weavy.ai остаются прежними. Figma и Figma Weave — разные продукты с независимыми системами кредитов и отдельными подписками. На Config 2026 запущены первые шаги интеграции: инструменты Weave внутри Figma и публикация Weave-воркфлоу в Figma Community. Персональные данные и контент не передаются между платформами.

Вывод: если вы уже пользуетесь Weavy/Weave — можно продолжать работать как раньше; но доступ к Figma Weave пока требует отдельной оплаты от основного тарифа Figma.

Сквозные выводы

  • Figma Weave — это node-based оркестратор десятков сторонних генеративных моделей, а не собственная AI-модель: главная ценность продукта — единый интерфейс, кредитная система и удобные узлы (итераторы, композитинг, маски) поверх Fal/Replicate/CivitAi/OpenAI/Google/Runway/Kling и др. Перед началом работы стоит один раз изучить раздел Models Comparison — это экономит кредиты и время на пробы.
  • Кредиты — сквозная валюта продукта. На Free/Starter они сгорают ежемесячно, на Pro/Team переносятся до 3 месяцев, top-up-кредиты не сгорают вовсе и живут год. Планировать апгрейд тарифа стоит после того, как израсходован текущий остаток — иначе он просто пропадёт при смене плана.
  • Верификация моделей («Verified by Figma») — это про юридические гарантии обработки данных, а не про качество или доступность; для коммерческого/конфиденциального контента стоит сверяться с этим статусом, особенно на Enterprise-плане, где неверифицированные модели требуют явного одобрения админа.
  • Итераторы + Compositor + Router — три узла, которые превращают Weave из инструмента «один промпт → один результат» в производственный конвейер: батч-генерация по CSV/массиву входов, многослойная сборка финальной композиции, разводка одного источника на несколько направлений.
  • Командная работа построена на трёх механиках, повторяющихся и в Team, и в Enterprise: Share (быстрый доступ), Change Owner (передача ответственности) и Workspace Files (общий обзор, доступен с Team-плана). Права редактирования чужого файла напрямую не выдаются — только дублирование.
  • API-интеграции у Weave пока нет (на момент сбора материала, июль 2026) — это стоит учитывать при планировании автоматизации вокруг продукта.
  • Продукт активно меняется после интеграции с Figma (Config 2026): инструменты Weave уже частично доступны прямо в Figma Design, а воркфлоу можно публиковать в Figma Community — это первые шаги к более глубокому слиянию двух продуктов, стоит следить за дальнейшими анонсами.
